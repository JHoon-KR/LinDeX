# 안전 및 복구

[English](../SAFETY.md) | [한국어](SAFETY.md)

## 반드시 지킬 규칙

- LinDeX를 위해 Android `/system`, `/vendor`, `/product`에 쓰거나 다시
  마운트하지 않습니다. 모듈은 `/system` 오버레이를 만들지 않습니다.
- 모듈을 설치하거나 업데이트하기 전에 DP를 물리적으로 분리합니다.
- 모듈 변경은 Android 일반 재부팅으로 활성화합니다.
- 업데이트 또는 제거 전에 `/data/local/debian`을 백업합니다. 제거는 의도적으로
  chroot와 내부 내용을 삭제합니다.
- 제거 또는 위험한 디스플레이 설정 변경 전에 WebUI **중지**를 사용합니다.
- 광범위한 프로세스 이름 종료나 Android 디스플레이 일괄 비활성 명령을 실행하지
  않습니다.
- 엄격한 zero-copy 모드는 CPU raw-pixel 복사로 조용히 폴백하면 안 됩니다.
- 수동 100/120/144Hz 모드는 자동 롤백이 없는 실험 기능으로 취급합니다.

## 자동 정리

각 모니터 세션은 정확한 PID/프로세스 그룹과 DRM lease 하나를 소유합니다. 정상
중지, 컴포지터 실패, 물리 케이블 분리는 해당 세션 디스크립터를 닫고 그 프로세스
그룹만 종료합니다. USB 입력 grab도 같은 세션 디스크립터 수명에 묶입니다.
Root 전용 세션 토큰이 launcher 자식에게 상속되므로 그룹 leader가 먼저 종료돼도
DRM FD를 가진 자식만 정확히 정리합니다. Connector 강제 분리는 EDID debounce를
건너뛰고, 재연결은 DP+EDID가 연속 2회 안정적으로 확인될 때까지 기다립니다.

재연결은 새 lease와 세션을 만들어야 합니다. 그렇지 않으면 DP를 분리한 채로
유지하고 관련 없는 Android 또는 Debian 프로세스를 종료하지 말고 문제 해결
흐름을 사용하세요.

## 로그 및 개인정보

Release 패키지는 영구 설정/세션/코덱 진단을 만들지 않고 오래된 동일 로그도
제거합니다. Dev 패키지는 크기가 제한된 순환 진단을 보존합니다. Dev 로그 일부를
공유하기 전에 기기 serial, 계정 token, cookie, 로컬 경로, 관련 없는 프로세스
데이터, 전체 Android 로그를 제거합니다.

## 복구 순서

1. DP를 물리적으로 분리합니다.
2. WebUI를 열고 **중지**를 누릅니다.
3. 상태가 중지됨으로 표시되고 USB 입력이 돌아왔는지 확인합니다.
4. 유효한 EDID가 표시된 뒤에만 DP를 다시 연결합니다.
5. 실패가 반복되면 DP를 분리한 채 dev 빌드로 한 번만 재현합니다.
6. 범위가 제한된 관련 오류만 수집하고 [문제 해결](TROUBLESHOOTING.md)을
   따릅니다.

WebUI를 사용할 수 없지만 모듈 명령이 있으면 범위가 제한된 중지 명령은 다음과
같습니다.

```sh
su -c 'debian-gpu-control stop'
```

모든 외부 디스플레이를 비활성화하거나 실행 파일 이름이 같은 모든 프로세스를
종료하는 임의 명령을 사용하지 않습니다.
